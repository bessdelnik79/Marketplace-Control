# P0.5: приёмка — 5 октября 2026

P0.5 принят в границах [плана](p0.5-plan.md) и [read-контракта](p0.5-read-contract.md): доступные суммы SKU и включённые ситуации раскрываются до сохранённых источников, контекст публикации сохраняется. Рост возвратов остаётся отключённым; неполные финансовые входы не объявляются подтверждёнными.

## Сохранённые данные рабочего кабинета

Использована штатная роль PostgreSQL без SUPERUSER/BYPASSRLS и существующий пользователь кабинета. Семь профилей чтения включают пять daily- и два legacy-диапазона; повторный daily-диапазон относится к предыдущей публикации.

| Источник и диапазон | Финансовое качество / основание | SKU | Ситуации | Проверенные вклады |
|---|---|---:|---:|---:|
| Daily 28 сентября — 4 октября | complete / после налога | 9 | 0 | 0 |
| Daily 21–27 сентября | complete / после налога | 9 | 1 убыток | 89 |
| Daily 31 августа — 6 сентября | complete / после налога | 9 | 3 убытка + штраф | 75 |
| Daily 1–30 сентября, два поколения | complete / после налога | 9 | 1 убыток | 327 |
| Legacy 21–27 сентября | partial / после налога | 8 | 0 | 94 |
| Legacy 6–12 апреля | partial / до налога | 8 | 0 | 105 |
| Предыдущая daily, 21–27 сентября | complete / после налога | 9 | 1 убыток | 89 |

Итого 779 проверенных вкладов на 476 страницах источников при лимите два; 288 раскрытий групп и налоговой базы. Это счётчики по профилям, а не число уникальных строк WB: диапазоны пересекаются. Недоступных источников среди выданных вкладов — 0. У первого диапазона нет денежных групп; отсутствие строк сохранено, источники не выдуманы.

Все контрольные суммы `matched`: строки SKU до налога, общие строки магазина, доступный итог, включённый налог и результат после налога. Общие строки не повторяются в каждом SKU и остаются теми же при фильтрации списка до пустого результата. Отдельно сверены налоговая база и её точные вклады; база не приравнивается сумме налога. Курсоры не теряют публикацию, магазин, период или группу.

Ситуации воспроизводят отрицательный результат до налога и знаковое сальдо штрафов с обратными операциями. Отключённое правило `return_growth` не входит в счётчик и не открывает карточку. Поэтому статус списка ситуаций остаётся `partial`, даже когда финансовая публикация полная.

Legacy 21–27 сентября сохраняет `operation_unclassified`. В апреле также сохраняются `product_link_missing` и `tax_source_unlinked`; неподтверждённый налог не включён, основание остаётся «до налога». Правило убытка не срабатывает по неполным входам. Эти ограничения относятся к финансовым данным/методике, а не закрываются интерфейсом P0.5.

## HTTP, неизменяемость и отсутствие загрузок

На работающем приложении VM пройдены 66 запросов: обзор → SKU → карточка → категория → источник → прежний обзор, а также все найденные ситуации → источники → возврат. Те же 66 запросов повторены через локальный HTTP-контур с реальными сессией, списком магазинов и финансовыми route factories, при заблокированном `globalThis.fetch` в процессе обработчиков. Чтение не сделало ни одной попытки внешнего fetch. Operational-read в проверочном контуре заменён пустым чтением; этот тест доказывает финансовые GET-пути P0.5. Развёрнутое приложение проверено отдельным HTTP-проходом.

Количество jobs и report versions до/после совпало (дельты 0/0); это дополнительное наблюдение количества записей, не аудит всей фоновой активности сервера. Финансовые входы, публикации, current pointers, ассортимент и подключения не изменялись. Для HTTP создавалась временная auth-сессия существующего пользователя, удалённая в `finally`.

Старая daily-публикация реально прочитана при наличии новой: прежние суммы, группы и evidence остаются согласованными; отдельная ссылка «Открыть новую публикацию» содержит новый ID и сохраняет магазин/период. Между кликами указатель рабочего кабинета не переключался специально; такую гонку покрывает одноразовая PostgreSQL-интеграция.

## Ревью, исправление и общие проверки

Независимое усиленное ревью проверило деньги, exact frozen report version + normalization, карту поколений по дням, RLS, raw allowlist, сортировку и disabled rules. Найден и исправлен возврат к сохранённому обзору отключённого магазина: explicit publication-контекст теперь читается перед заглушкой подключения. Собственная сохранённая публикация доступна, malformed/foreign ID возвращают 400/404. Независимые регрессионные тесты — 21/21.

Итоговые проверки на VM без Docker: приложение 579/579, схема БД 176/176, PostgreSQL-интеграции 12/12. Словарь БД сгенерирован и не изменился. Для PGlite использован тот же harness освобождения уже закрытых инстансов, описанный в [сводке пункта 4](p0.5-situations-2026-10-05.md); набор схемных проверок не изменён. Светлая/тёмная темы, 390 px и клавиатурный фокус приняты в пунктах 3–4; текущее исправление касается серверного выбора сохранённой публикации.

Повторяемый opt-in runner: [p05-live.acceptance.mjs](../db/tests/p05-live.acceptance.mjs), запуск и приватный формат контекста — [db/README](../db/README.md). Raw, идентификаторы кабинета, финансовые суммы и credentials в этот отчёт и Git не включены.

Граница готовности: приняты поддержанные публикации и доказанные правила; неизвестные финансовые операции остаются fail-closed. Объёмная история всего кабинета, все виды редких WB-операций и включение роста возвратов не объявляются проверенными этой приёмкой.
