# Marketplace Control — формулы финансовых показателей

Версия 0.1 · 16 сентября 2026 года.

Документ хранит формулы отдельно от интерфейса и исходного кода. Изменение трактовки создаёт новую версию методики; опубликованные результаты не пересчитываются незаметно.

## Статус версии

Формулы ниже — первая техническая спецификация для импорта финансовых отчётов WB. До сверки с реальным кабинетом они не используются для публикации полной прибыли на странице «Обзор».

## Общие правила

- Все суммы хранятся в рублях как точные десятичные числа PostgreSQL `numeric(20,4)`.
- Доходы имеют положительный знак, расходы — отрицательный.
- Отсутствующее значение не равно нулю.
- Итоги считаются только по принятой версии отчёта.
- Аналитика ограничивается выбранными товарами, но исходный отчёт сохраняется полностью.
- Перечисление денег от WB — сверочная сумма, а не дополнительный доход.
- Оперативные заказы не участвуют в финансовом результате до появления в отчёте реализации.

## Компоненты отчёта WB

Обозначение `Σ` означает сумму строк принятой версии отчёта за выбранный период.

| Компонент | Поле WB | Формула знака | Категория |
|---|---|---|---|
| Выручка продажи | `retailAmount` | `+abs(value)` для операции продажи | `revenue` |
| Возврат выручки | `retailAmount` | `-abs(value)` для операции возврата | `revenue_return` |
| Комиссия WB | `ppvzSalesCommission` | `-abs(value)` | `commission` |
| Эквайринг | `acquiringFee` | `-abs(value)` | `acquiring` |
| Логистика | `deliveryService` | `-abs(value)` | `logistics` |
| Возмещённая логистика | `rebillLogisticCost` | `-abs(value)` | `logistics` |
| Хранение | `paidStorage` | `-abs(value)` | `storage` |
| Приёмка | `paidAcceptance` | `-abs(value)` | `acceptance` |
| Штрафы | `penalty` | `-abs(value)` | `penalty` |
| Удержания | `deduction` | `-abs(value)` | `deduction` |
| Дополнительная выплата | `additionalPayment` | `+abs(value)` | `additional_payment` |
| Перечисление продавцу | `forPay` | исходный знак, только для сверки | `payout` |

Нулевой компонент не сохраняется. Новые или нераспознанные операции получают статус `unclassified` и не включаются в опубликованный результат автоматически.

## Выручка

```text
Выручка = Σ revenue + Σ revenue_return
```

Возврат хранится отрицательным вкладом. Продажи и возвраты определяются подтверждённым правилом по `docTypeName` и `sellerOperName`.

## Расходы WB

```text
Расходы WB =
    Σ commission
  + Σ acquiring
  + Σ logistics
  + Σ storage
  + Σ acceptance
  + Σ penalty
  + Σ deduction
```

Все перечисленные компоненты хранятся отрицательными. Дополнительные выплаты не уменьшают расходы — это отдельный положительный компонент.

## Результат по данным WB до себестоимости и налога

```text
Результат WB =
    Выручка
  + Расходы WB
  + Σ additional_payment
  + Σ прочих подтверждённых корректировок
```

`forPay` в формулу не добавляется. Он используется для сверки рассчитанных компонентов с суммой, предназначенной к перечислению продавцу.

## Себестоимость

Для продажи:

```text
Себестоимость строки = -Количество × Себестоимость варианта на дату операции
```

Значение для варианта выбирается версионно: используется последняя запись `variant_costs.effective_from`, которая не позже даты операции, и её текущая версия `cost_versions`. Загруженный файл может содержать разные даты начала для одного варианта. Отсутствующее значение не заменяется нулём.

Для возврата ранее проданного товара:

```text
Возврат себестоимости = +Количество возврата × Себестоимость варианта на дату исходной продажи
```

До реализации связи возврата с исходной продажей возврат себестоимости не публикуется как полный. Отсутствующая себестоимость создаёт причину неполноты, а не нулевой расход.

## Доступный финансовый результат

```text
Доступный результат =
    Результат WB
  + Себестоимость
  + Дополнительные расходы пользователя
```

Этот показатель ещё не называется чистой прибылью, если налоговые настройки отсутствуют или часть расходов не заполнена.

## Налог и чистая прибыль

Пользовательские настройки хранятся версионно на уровне бизнеса. Пилотный режим — УСН «Доходы» с фактической ставкой пользователя и отдельным статусом НДС. Схема предусматривает УСН «Доходы минус расходы» и ОСНО, но не применяет к ним приблизительную формулу до появления отдельной проверенной версии методики.

НДС не выводится из названия режима: для УСН предусмотрены варианты с НДС и без НДС. Статус `unmodeled` означает, что НДС не рассчитан, а не освобождение или нулевую сумму.

Исполняемая формула, доказательства налоговой базы и фиксация версии настройки относятся к P0.3. Будущий пилотный показатель называется **«Расчётный налог УСН по доступной базе до уменьшений»**, поскольку приложение не знает все доходы бизнеса, страховые уменьшения и авансы. До этого:

```text
Чистая прибыль = недоступна
```

Если настройка отсутствует, налог не участвует в расчёте и не подставляется как ноль. Интерфейс показывает «Прибыль по доступным данным» и конкретную причину, например «Налог не учтён: не заполнена налоговая ставка». Неподдерживаемый режим даёт `tax_method_unsupported`.

## Сравнение периодов

```text
Изменение, ₽ = Результат текущего периода − Результат предыдущего периода

Изменение, % =
  (Результат текущего периода − Результат предыдущего периода)
  / abs(Результат предыдущего периода) × 100%
```

Процент не рассчитывается, если предыдущий результат равен нулю или периоды несопоставимы по покрытию данных.

## Контроль качества формул

Перед публикацией должны выполняться условия:

1. каждый финансовый компонент связан с исходной строкой WB;
2. один компонент не учитывается дважды;
3. используется только одна принятая версия каждого отчёта;
4. все строки выбранного периода имеют известное покрытие;
5. неизвестные операции явно перечислены в причинах неполноты;
6. сумма результата воспроизводится из сохранённых источников.
