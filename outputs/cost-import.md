# Импорт себестоимости товаров

Страница `/costs` позволяет изменить себестоимость каждого варианта выбранного товара отдельно или массово загрузить её из файла. Это доступно также для восстановленных исторических товаров.

В строке варианта нажмите «Указать себестоимость» или «Изменить себестоимость», введите сумму и дату «Действует с», затем сохраните. При исправлении используется существующая дата; для нового значения на будущее нужно изменить дату. Для прошлых продаж указывается соответствующая историческая дата. Допускаются точка или запятая и до четырёх знаков после разделителя. Одинаковая сумма для того же варианта и даты не создаёт лишней версии.

Ручное сохранение (`POST /costs/save`) проверяет выбранный активный вариант и магазин в контексте бизнеса. Запись доступна владельцу и редактору; просмотр — также viewer. Сохраняется новая неизменяемая версия с источником `manual` и автором. Изменение текущей версии запускает локальный финансовый пересчёт без запроса к WB. Ошибка сохраняет введённые значения в форме; при работе со вторым магазином сохраняется его контекст. Импорт CSV/TSV/XLSX продолжает работать отдельно.

## Рабочий сценарий

1. Пользователь скачивает CSV-шаблон. В нём уже перечислены выбранные товары и варианты, а для новых значений проставлена текущая дата по Москве.
2. Пользователь заполняет столбец `Себестоимость, ₽` и при необходимости меняет `Действует с`.
3. Приложение проверяет весь файл. При любой ошибке ни одна сумма не применяется; на странице показываются номера проблемных строк.
4. Корректный файл создаёт новые версии себестоимости. Повтор той же суммы для того же варианта и даты безопасно пропускается.

## Форматы и столбцы

Поддерживаются UTF-8 CSV/TSV и XLSX. Старый XLS нужно сначала сохранить как XLSX или CSV. SVG — формат изображения, а не таблицы, поэтому для импорта данных он не поддерживается.

Обязательные столбцы:

- `Артикул WB`;
- `ID варианта` или `Штрихкод`;
- `Себестоимость, ₽` — неотрицательная сумма в рублях, до четырёх знаков после запятой;
- `Действует с` — дата `ДД.ММ.ГГГГ` или `ГГГГ-ММ-ДД`.

Артикулы, ID и особенно штрихкоды следует хранить в Excel как текст. Формулы не принимаются: перед загрузкой их нужно заменить вычисленными значениями.

## Ограничения и хранение

- размер файла — до 5 МБ;
- до 10 000 строк и 30 столбцов;
- распакованный XLSX — до 25 МБ и 200 частей;
- импортируется только себестоимость вариантов выбранных товаров текущего магазина;
- один файл применяется атомарно;
- в PostgreSQL сохраняются имя и контрольная сумма файла, проверенные значения строк, статус импорта и версионная история сумм;
- исходный файл целиком в текущем MVP не сохраняется.

Эффективная себестоимость для операции выбирается по варианту товара как последнее значение с датой начала, не превышающей дату операции. История не перезаписывается.

## Структура модуля

Себестоимость — первый модуль, выделенный из общих файлов приложения. Логика модуля находится в `app/modules/costs/`, а его интерфейс — в `app/frontend/`:

| Файл | Ответственность |
|---|---|
| `costs.import.mjs` | CSV-шаблон, чтение CSV/TSV/XLSX, проверка формата и значений |
| `costs.repository.mjs` | Чтение состояния, ручное сохранение, атомарный импорт, версии сумм и проверка прав записи |
| `app/frontend/costs.page.mjs` | HTML страницы, покрытие себестоимостью и ошибки строк |
| `costs.routes.mjs` | GET страницы и шаблона, POST ручного сохранения и импорта, проверка доступа и лимиты |
| `*.test.mjs` | Модульные проверки импорта, страницы и HTTP-обработчиков рядом с соответствующим кодом |

`app/db.mjs` подключает репозиторий через существующий транзакционный контекст и сохраняет экспорты `getCostState`, `importVariantCosts` и `saveVariantCost`. `app/frontend/pages.mjs` передаёт общую оболочку и форматирование в фабрику страницы, сохраняя экспорт `costPage`. `app/server.mjs` подключает обработчик маршрутов. Передача зависимостей позволяет модулю не импортировать эти общие файлы обратно и не создавать циклы.

Общие CSS-классы остаются в `app/frontend/public/`: они используются также расходами и налогами. Схема БД, адреса страниц, форматы файлов и правила импорта при выделении модуля не меняются.

Проверки приложения: `npm test`. PostgreSQL-регрессия — отдельно, только на одноразовой тестовой БД:

```sh
COSTS_INTEGRATION_DATABASE_URL=postgresql:///marketplace_control_costs_test node db/tests/costs.integration.mjs
```

Проверяются точные суммы, повторный импорт без новой версии, исправление с новой версией, атомарный отказ при ошибке строки, запрет записи для viewer и изоляция магазинов.
