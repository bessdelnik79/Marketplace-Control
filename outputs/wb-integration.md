# Подключение Wildberries API

Первый этап интеграции принимает токен в настройках магазина, проверяет его через официальные методы Wildberries и сохраняет только после успешной проверки.

## Требования к токену

- персональный токен для реальных данных, не тестовый; базовый токен можно сохранить для каталога, но финансовый модуль с ним не запускается;
- доступ только для чтения;
- категории «Контент», «Аналитика», «Статистика» и «Финансы»;
- «Продвижение» можно добавить сразу для будущей рекламной аналитики.

Приложение декодирует служебные поля JWT локально, проверяет срок действия и категории, затем вызывает `https://common-api.wildberries.ru/ping` и `https://common-api.wildberries.ru/api/v1/seller-info` с заголовком `Authorization: Bearer <token>`. Ответ seller-info связывает магазин с постоянным `sid` кабинета WB. Другой кабинет нельзя незаметно подключить вместо уже назначенного. Если после успешного `ping` вспомогательный `seller-info` отвечает `429`, подключение завершается по подписанному `sid` токена: этот метод имеет отдельный лимит 1 запрос в минуту и не должен блокировать повторное сохранение.

Официальные источники: [общая документация WB API](https://dev.wildberries.ru/docs/openapi/api-information), [система авторизации](https://dev.wildberries.ru/knowledge-base/articles/019d49a1-0d73-71e9-be3e-b2c44567470c/sistema-avtorizatsii-wb-api).

## Хранение

Токен не записывается в журналы и никогда не возвращается в HTML. Перед записью он шифруется AES-256-GCM отдельным 32-байтовым ключом `WB_TOKEN_ENCRYPTION_KEY`. Ключ хранится только в конфигурации среды VM, шифротекст, nonce и тег аутентификации — в `mc.connection_secrets` под RLS. `mc.connections.secret_ref` содержит только внутреннюю ссылку, не секрет.

После подключения создаются или активируются потоки `catalog` и `financial_reports`. Каталог загружается сразу. Финансовые отчёты начинают загружаться после подтверждения товаров и затем обновляются по расписанию или вручную. Исходные страницы финансового API сохраняются сжатыми и зашифрованными, а в PostgreSQL создаются версионные отчёты, операции и финансовые компоненты. Подробный контракт: [финансовые отчёты](financial-reports.md), [формулы показателей](financial-formulas.md).

Для текущего частного MVP нужен именно персональный токен: только чтение, категория «Финансы». Сервисные токены требуют отдельного клиентского секрета и в этой версии не поддерживаются. При замене базового токена на персональный заблокированный финансовый поток автоматически активируется снова.

## Диагностика

При попытке подключить кабинет WB, уже добавленный в другом магазине этого бизнеса, красная плашка показывает «Этот магазин уже добавлен.» (HTTP 409). Проверка существующей уникальности кабинета действует и для того же токена, и для другого токена того же кабинета; правила сохранения подключения не меняются.

На VM сообщения приложения сохраняет системный журнал службы `marketplace-control.service`. Ошибки подключения отмечены префиксом `[WB connection failed]`, а финансовой загрузки — `[WB financial reports failed]`. Записи содержат внутренний код, HTTP-статус WB и название метода, но не содержат API-токен или строки отчёта. Последние записи можно посмотреть командой `sudo journalctl -u marketplace-control.service -n 100 --no-pager`.
