# SQL: повторные чтения финансового Обзора — 11 октября 2026

Устранены повторные чтения дневного финансового результата при загрузке Обзора. На проверенном кабинете обычный финансовый Обзор выполняет 53 команды БД вместо 85. Полные ответы до и после изменения совпали во всех восьми проверенных сценариях. Это продолжение [оптимизации JIT, индексов и оперативного чтения](sql-performance-2026-10-10.md); исходная версия для сравнения — `8799bf4`.

## Изменения по порядку

1. Ситуации обычного Обзора переиспользуют уже прочитанные дни, строки результатов, причины и налоговые факты текущего периода. Их собственное чтение сокращается с 17 до 13 команд, включая транзакцию и проверки доступа. Область хранения ограничена одним запросом пользователя через `AsyncLocalStorage`; ключ содержит бизнес, магазин, публикацию и точные границы периода. Читатель получает отдельную копию строк, а область очищается по завершении или ошибке. Исторические периоды в этот кеш не копируются.
2. Текущий и четыре сравнительных периода читаются семью пакетными SELECT вместо 35. Каждый диапазон отдельно сопоставляется с замороженной картой дней и поколений, затем агрегируется существующей функцией. Налог округляется отдельно по каждому периоду; причины неполноты, свежесть исходников, ссылки на отчёты и исключённые товары также остаются привязаны к своему диапазону. Публикации прежних методов и отсутствующие данные сохраняют прежние fallback и состояния.
3. Проверены полное совпадение результатов, изоляция доступа и ограниченная параллельная нагрузка на VM с настоящим PostgreSQL. Независимое ревью финансовых границ и RLS завершено без подтверждённых дефектов.

Переиспользование не заменяет проверку членства, магазина, тарифа и совместимости всех поколений публикации. Чтение ситуаций сохраняет собственную read-only транзакцию `REPEATABLE READ`; истечение тарифа между чтениями отклоняет запрос. Самостоятельные drill-down чтения и закреплённые контексты сохраняют прежний путь. Технические поля сырых строк не добавляются в публичный ответ.

## Замеры

Замеры выполнены на VM с двумя CPU и действующей БД под ролью приложения. Диагностический процесс вызывает настоящие обработчики Обзора, включая readers и генерацию HTML. Время ниже исключает HTTP-аутентификацию и сеть. Запросы к рабочей БД ограничены чтением; обращения к WB и запись финансовых данных не выполнялись. Новый код проверялся из отдельного checkout на той же VM.

| Показатель | До изменения | После изменения |
|---|---:|---:|
| Команды БД, один обычный Обзор | 85 | 53 |
| Команды БД, финансовый reader с пятью периодами | 46 | 18 |
| Прогретый Обзор, два последовательных замера | 163,82–166,61 мс | 139,63–145,00 мс |
| Два одновременных Обзора, время всей группы | 259,20 мс | 213,50 мс |
| Пять одновременных Обзоров, время всей группы | 495,71 мс | 479,75 мс |
| Пять одновременных Обзоров, команды БД | 425 | 265 |
| Пять одновременных Обзоров, CPU PostgreSQL | 570 мс | 470 мс |
| Пять одновременных Обзоров, CPU диагностического Node.js | 283,59 мс | 248,19 мс |

Команды включают управление транзакциями и RLS-контекстом. Сокращение 35 → 7 относится только к SELECT дневных финансовых данных и метаданных. CPU PostgreSQL измерен по процессам соединений диагностического пула, включая новые процессы; перед параллельным прогоном прогреты пять соединений. Это накопленное процессорное время, а не процент загрузки VM.

Короткие прогоны подтверждают уменьшение числа запросов и CPU при пяти одновременных чтениях на проверенном кабинете. Они не доказывают устранение любого пика 75%: общая загрузка VM колеблется, а при двух одновременных чтениях CPU PostgreSQL составил одинаковые 240 мс. Снимки RSS после пяти чтений составили 121,12 и 123,70 МиБ в разных процессах; по ним нельзя утверждать уменьшение памяти или отсутствие утечек при длительной нагрузке.

## Проверки

- На VM напрямую, без Docker: 816/816 тестов приложения; 181 проверка схемы, 112 таблиц.
- PostgreSQL-интеграции: P0.3 — 13/13; финансовое сравнение P0.4 — 7/7; оперативные snapshots — 10/10; кэш финансовых возвратов — 14/14; оперативные возвраты — 15/15. Всего 59/59.
- Финансовое сравнение выполнялось обычной ролью `NOSUPERUSER NOBYPASSRLS` в отдельной одноразовой БД. Новые fixtures проверяют смешанные поколения, отдельное округление налогов, пересечение диапазонов, partial/unavailable и тариф, истекающий внутри запроса.
- На действующих сохранённых данных сравнивались все поля финансового reader и состояния настоящего обработчика Обзора: последняя неделя, август, март и произвольный диапазон 3–18 сентября. Все восемь ответов совпали; команд стало 46 → 18 / 85 → 53 для последней недели и 45 → 17 / 84 → 52 для явных диапазонов.
- Проверены изоляция параллельных и вложенных областей, очистка после ошибки и завершения, отдельные копии строк и совпадение ситуаций с самостоятельным чтением.

Схема, индексы, метод финансового расчёта и сохранённые публикации этим изменением не меняются. Следующий замер следует делать на фактической нагрузке и по приросту статистики после развёртывания: короткая серия одновременных чтений не заменяет длительный нагрузочный тест.
