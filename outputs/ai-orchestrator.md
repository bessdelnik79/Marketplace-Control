# AI-оркестратор Marketplace Control

Основная задача Codex координирует работу в рамках запроса пользователя: исследование, реализацию, интеграцию, проверки и сохранение результата. Она не выбирает следующий этап MVP самостоятельно. Общие правила проекта — в [AGENTS.md](../AGENTS.md), профили агентов — в `.codex/agents/`.

## Делегирование и контекст

- Для задач с независимыми частями, несколькими подсистемами или повышенным риском оцени пользу разделения работы. Используй параллельных агентов там, где их задания независимы.
- Полный цикл «исследователь → исполнители → reviewer» не обязателен для каждой задачи. Простую локальную правку основной агент выполняет сам; условия независимого ревью приведены ниже.
- Передавай узкое задание: ожидаемый результат, необходимые пути и символы, ограничения, проверки. Не копируй всю историю обсуждения и документацию без необходимости.
- Используй результаты уже выполненного исследования. Повторное чтение оправдано изменением кода, пробелом в отчёте или противоречием; проверка итогового diff и результата остаётся обязательной.

| Профиль | Ответственность |
|---|---|
| `mc_explorer` | Только чтение: точки входа, зависимости, риски, тесты и границы рабочих частей. |
| `mc_implementer` | Реализация одной части исключительно в назначенных путях. |
| `mc_reviewer` | Только чтение: независимая проверка итогового diff, регрессий, безопасности и покрытия тестами. |

## Параллельная работа

Одновременно допускаются до трёх субагентов и до двух агентов с правом записи, включая основного. Все работают в общем checkout.

1. До запуска исполнителя основной агент явно назначает ему исключительный список файлов или директорий и запрещает изменение остальных путей.
2. Параллельная запись разрешена только в непересекающиеся файлы. Общие файлы и изменения общего интерфейса обрабатываются последовательно.
3. Перед правками исполнитель читает применимые инструкции, проверяет `git status` и текущие версии назначенных файлов. Незнакомые правки, конфликт или необходимость выйти за границы задания — блокер: прекратить запись и сообщить основному агенту.
4. Нельзя откатывать чужую работу, широко форматировать соседний код или самостоятельно расширять задачу. Только основной агент выполняет `git add`, `git commit`, `git push`, переключение веток, публикацию и развёртывание.

Отчёт субагента должен быть кратким: результат; изменённые или исследованные пути и ключевые символы; команды проверок с результатами; риски и блокеры. Полные файлы и успешные логи в отчёт не копируются; для замечаний нужны конкретные места и доказательства.

## Интеграция и проверки

Основной агент дожидается исполнителей, проверяет diff и фактический результат, интегрирует изменения и исправляет подтверждённые замечания. Отчёт агента не заменяет эту проверку.

| Изменение | Проверки и ревью |
|---|---|
| Только документация, включая текстовые инструкции | Локальная статическая проверка, включая `git diff --check`; отдельный reviewer и VM не обязательны. |
| Конфигурация Codex | Проверка синтаксиса и diff, независимый reviewer; VM не нужна, если не затронута среда приложения. |
| Простые визуальные правки без изменения поведения, прав доступа, форм и финансовых данных | Проверка отображения на VM и подходящие целевые проверки; отдельный reviewer не обязателен. |
| Остальные изменения приложения | Независимый reviewer, тесты затронутого модуля и подходящие общие проверки; итоговая проверка на VM. |
| БД, аутентификация, финансовые расчёты, внешние API и безопасность | Усиленное независимое ревью, полный подходящий набор тестов и итоговый прогон на VM. Для схемы БД, расчётов и ограничений целостности — полный набор тестов приложения и БД. |

Итоговые проверки приложения выполняются на VM `marketplacecontrol` напрямую, без Docker; локальные прогоны вспомогательные. Недоступные проверки указываются как ограничения. Уже пройденные тяжёлые проверки повторяются только после влияющих на них изменений или при нерешённых сомнениях.

После проверок основной агент проверяет состав staging, объединяет связанные правки запроса в один содержательный коммит и выполняет `git push origin main`. В итоговом ответе — результат, проверки, ограничения при наличии и короткий идентификатор отправленного коммита.
