# Marketplace Control

Сервис для селлера / собственника: следить, всё ли в порядке в бизнесе, замечать существенные проблемы и проверять утверждения сотрудников по доступным данным.

Текущая концепция: [Концепция продукта — Marketplace Control](outputs/marketplace-control-concept.md).

Актуальная готовность продукта и порядок следующих работ: [Статус и план MVP](outputs/mvp-status.md).

Работа Codex над репозиторием координируется проектным [AI-оркестратором](outputs/ai-orchestrator.md): для нетривиальных задач он разделяет независимые части между профильными агентами, проводит независимое ревью и оставляет коммит, push и итоговую проверку за основной задачей.

Первая итерация БД: [схема и решения](outputs/database-v1.md), [полный словарь полей](outputs/database-v1-dictionary.md), [миграция и проверки](db/README.md). Документ БД учитывает последующие уточнения MVP, тарифов и выбора товаров; исходная концепция сохранена без изменений.

## Структура кода

Предметные функции приложения сгруппированы в `app/modules/`: авторизация, магазины, каталог, себестоимость, расходы, налоги, отчёты и расчёт. Подключение к БД, письма, шифрование и хранение файлов находятся в `app/infrastructure/`. Все страницы, браузерный JS, стили и изображения — в `app/frontend/`. [Карта файлов и обязанностей](app/README.md).

`app/server.mjs` собирает HTTP-приложение, `app/db.mjs` сохраняет прежние имена экспортов для существующих вызовов; запросы к БД находятся рядом со своими модулями в `*.repository.mjs`. Миграции и интеграционные проверки остаются в `db/`.

`npm test` рекурсивно запускает `*.test.mjs` внутри `app/`; для целевого прогона используй `node --test <путь-к-тесту.test.mjs>`.

## Среда MVP

Итоговые тесты и тестовые развёртывания выполняются на выделенной VirtualBox VM `marketplace_control` напрямую, без Docker. На VM работают PostgreSQL и системная служба приложения; проверенные изменения ветки `main` автоматически устанавливаются из GitHub. Инструкция проверки: [доступ к тестовой VM](outputs/vm-access.md).

Локальный запуск используется только для быстрой разработки и не заменяет итоговую проверку на VM:

```powershell
Copy-Item .env.example .env
npm install
npm start
```

Для такого запуска нужен доступный PostgreSQL и заполненные переменные в `.env`. Файл `.env`, пароли, токены и ключи шифрования в GitHub не добавляются. Существующие Docker-файлы сохранены как задел, но сейчас не являются актуальной средой тестирования проекта.

## Регистрация и вход

На тестовой VM можно временно отключить email-код: задайте системной службе `EMAIL_VERIFICATION_REQUIRED=false` и перезапустите приложение. Регистрация сразу создаёт аккаунт и сессию, письма не отправляются. Email при этом не помечается подтверждённым. В режиме `NODE_ENV=production` подтверждение обязательно независимо от переключателя; без переключателя оно также включено.

В первом исполняемом модуле доступны регистрация по имени, email и паролю с шестизначным кодом подтверждения, вход через Яндекс ID, защищённая стартовая страница и выход. При регистрации автоматически создаются бизнес, роль владельца и бесплатная подписка. Пароли хранятся как стойкие `scrypt`-хэши, а браузер получает отдельную защищённую сессию на 30 дней. Лимиты запросов хранятся в PostgreSQL; при подозрительной активности может включаться Яндекс SmartCaptcha. Без SMTP локальный код показывается на странице проверки. Внешние интеграции включаются ключами из `.env`.

## Подключение Wildberries

В настройках магазина можно проверить и подключить токен WB с категориями «Контент», «Аналитика», «Статистика» и «Финансы». Токен проверяется через официальные методы WB и сохраняется в PostgreSQL только как AES-256-GCM шифротекст. Для каждой среды требуется отдельный `WB_TOKEN_ENCRYPTION_KEY` — 32 случайных байта в Base64. Подробности: [интеграция Wildberries API](outputs/wb-integration.md).

После подключения в фоне загружается каталог WB. В настройках пользователь выбирает товары для анализа в пределах текущего тарифа; подтверждение сохраняется атомарно. Подробности: [каталог и выбор товаров](outputs/catalog-sync.md).

После подтверждения товаров приложение загружает детализацию еженедельных финансовых отчётов WB, хранит зашифрованные исходные страницы и создаёт версионные операции без повторного учёта. Статус и ручное обновление доступны в настройках. Подробности: [загрузка финансовых отчётов](outputs/financial-reports.md), [формулы показателей](outputs/financial-formulas.md).

Для выбранных товаров работает отдельная страница массового ввода себестоимости: пользователь скачивает заполненный шаблон и загружает CSV, TSV или XLSX. Импорт атомарный и версионный; ошибки показываются по строкам. Подробности: [импорт себестоимости](outputs/cost-import.md).

Дополнительные расходы вводятся вручную или атомарным импортом на странице `/expenses`, а налоговый режим, фактическая ставка и независимый статус НДС — на странице `/taxes`. Все исправления сохраняются новыми версиями. Отсутствующий налог не считается нулём: будущий результат останется доступным, но будет отмечен как неполный с конкретной причиной. Подробности: [налоги и дополнительные расходы P0.2](outputs/user-financial-inputs.md), [рабочий план и статус](outputs/p0.2-plan.md).

P0.3 завершён: воспроизводимый недельный расчёт закрепляет версии входов, доказательства, налог по выбранным SKU, period-specific quality и атомарную публикацию. Следующий этап — подключение сохранённого результата к реальному обзору по [плану P0.4](outputs/p0.4-plan.md); новые неподтверждённые операции WB продолжают исключаться fail-closed.

Архив: [исходная концепция, версия 0.1](outputs/marketplace-control-concept-v0.1.md). Сохранена без изменений; актуальные решения изложены в текущей концепции.

Документ включает позиционирование, главный экран, финансовую методику, оперативный контроль, продвижение, прибыль по товарам и регионам, оборотный капитал, контрольные точки, MVP и открытые вопросы.
