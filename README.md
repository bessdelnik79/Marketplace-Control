# Marketplace Control

Сервис для селлера / собственника: следить, всё ли в порядке в бизнесе, замечать существенные проблемы и проверять утверждения сотрудников по доступным данным.

Текущая концепция: [Концепция продукта — Marketplace Control](outputs/marketplace-control-concept.md).

Первая итерация БД: [схема и решения](outputs/database-v1.md), [полный словарь полей](outputs/database-v1-dictionary.md), [миграция и проверки](db/README.md). Документ БД учитывает последующие уточнения MVP, тарифов и выбора товаров; исходная концепция сохранена без изменений.

## Локальный запуск MVP

Для первых тестов и MVP проект разворачивается локально. VPS пока не используется.

После установки Docker Desktop запустите из корня проекта:

```powershell
Copy-Item .env.example .env
.\scripts\local-start.ps1
```

Команда собирает и запускает единый контейнер `marketplace-control`. Внутри него работают PostgreSQL 17, веб-приложение, мигратор и SMTP-клиент. База доступна только на `127.0.0.1:5432`, интерфейс — на `http://localhost:3000`. Остановка не удаляет данные:

```powershell
.\scripts\local-stop.ps1
```

Настройки находятся в `.env`; этот файл не попадает в GitHub. Пароль по умолчанию предназначен только для локальной разработки.

## Регистрация и вход

На тестовой VM можно временно отключить email-код: задайте системной службе `EMAIL_VERIFICATION_REQUIRED=false` и перезапустите приложение. Регистрация сразу создаёт аккаунт и сессию, письма не отправляются. Email при этом не помечается подтверждённым. В режиме `NODE_ENV=production` подтверждение обязательно независимо от переключателя; без переключателя оно также включено.

В первом исполняемом модуле доступны регистрация по имени, email и паролю с шестизначным кодом подтверждения, вход через Яндекс ID, защищённая стартовая страница и выход. При регистрации автоматически создаются бизнес, роль владельца и бесплатная подписка. Пароли хранятся как стойкие `scrypt`-хэши, а браузер получает отдельную защищённую сессию на 30 дней. Лимиты запросов хранятся в PostgreSQL; при подозрительной активности может включаться Яндекс SmartCaptcha. Без SMTP локальный код показывается на странице проверки. Внешние интеграции включаются ключами из `.env`.

## Подключение Wildberries

В настройках магазина можно проверить и подключить токен WB с категориями «Контент», «Аналитика», «Статистика» и «Финансы». Токен проверяется через официальные методы WB и сохраняется в PostgreSQL только как AES-256-GCM шифротекст. Для каждой среды требуется отдельный `WB_TOKEN_ENCRYPTION_KEY` — 32 случайных байта в Base64. Подробности: [интеграция Wildberries API](outputs/wb-integration.md).

Архив: [исходная концепция, версия 0.1](outputs/marketplace-control-concept-v0.1.md). Сохранена без изменений; актуальные решения изложены в текущей концепции.

Документ включает позиционирование, главный экран, финансовую методику, оперативный контроль, продвижение, прибыль по товарам и регионам, оборотный капитал, контрольные точки, MVP и открытые вопросы.
