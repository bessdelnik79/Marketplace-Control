# Правила работы над Marketplace Control

## Сохранение в GitHub

Пользователь поручил сохранять всю работу по проекту сразу в GitHub.

- После каждого завершённого изменения файлов выполнить подходящие проверки, создать содержательный коммит и отправить его в настроенный GitHub remote. Не откладывать отправку до отдельной просьбы пользователя.
- Это постоянное разрешение на обычные коммиты и push изменений в рамках порученной работы. Не запрашивать повторное подтверждение для этих действий.
- Не включать секреты, токены, персональные выгрузки WB, содержимое локальных БД, зависимости и временные файлы. Рабочие материалы находятся в `work/`, пользовательские документы — в `outputs/`.
- Перед коммитом проверять состав изменений. Не перезаписывать чужую работу и не использовать force push. При конфликте или проблеме доступа сохранить локальный результат и явно сообщить, что не отправлено.
- Просьбы «только обсуждаем» и «ничего не создавай» означают обсуждение без изменения файлов. При разрешённом создании или обновлении документов они также сохраняются в GitHub.

### Быстрый порядок работы

- Для обычного небольшого изменения: выполнить одну подходящую проверку, затем без дополнительных промежуточных согласований сделать `git add`, один содержательный коммит и `git push origin main`.
- Не повторять уже пройденные тяжёлые проверки, если изменение их не затрагивает. Полный набор тестов запускать для изменений схемы БД, расчётов и ограничений целостности.
- Объединять все связанные правки одного запроса в один коммит. После успешной отправки сообщать пользователю только итог и короткий идентификатор коммита.

## Текущий контекст

- Актуальная реализованная схема первого MVP: `db/migrations/001_initial.sql`.
- Принятые решения и ограничения первой итерации: `outputs/database-v1.md`.
- Словарь БД: `outputs/database-v1-dictionary.md`.
- Применение и проверки: `db/README.md`, `db/tests/schema.test.mjs`.
- Исходная концепция: `outputs/marketplace-control-concept.md`. Последующие согласованные уточнения отражены в документах БД.
- Для первых тестов и MVP используется локальное развёртывание через `compose.yaml`. Локальный PostgreSQL запущен в Docker Desktop; VPS пока не используется.
